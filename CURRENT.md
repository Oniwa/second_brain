**New finding, opened mid-activation:** the any-delta-triggers-full-recompile problem the cadence fix solved for content-creator *people* is general — **topics still recompile in full on any `thought_count` delta, however small.** First live run cost ~$4: ~40 topics had genuine but tiny deltas (+1 to +6 thoughts each), but the big topics (`AI agents` 331, `prompt engineering` 138, `system design` 112...) still paid full re-synthesis cost for a 1-thought change. Unlike people, topics have **no duplication-based escape hatch** (measured: 90%+ topic-to-topic overlap is normal multi-tagging, not redundancy) — so a delta threshold means accepting staleness on exactly the pages that are large *because* they're highest-value. Deliberately not solved mid-run. **Leading candidate, new stub `plans/in_progress/wiki_cowork_synthesis.md`:** route expensive pages through Claude Cowork's Scheduled Tasks — confirmed subscription billing (not metered API), real cloud-hosted scheduling, Supabase connector, full Windows parity. Needs a proof-of-concept before design. See `plans/in_progress/wiki_compile_cost_control.md`'s "Follow-up opened 2026-08-07" section and roadmap #7.

**Also found and fixed:** `docs/rpi-setup.md` and `setup_rpi.py`'s printed instructions both said `git pull origin develop`, but the Pi is actually checked out to `main` (confirmed live) — following that instruction literally would have silently diverged the Pi's local `main` from `origin/main`. Fixed to `git pull origin main`, matching a real gitflow model going forward (main = deployed, develop = active work).

**⚠️ Migration caveat (still open, unrelated to this session):** `010_workspace_backfill.sql` is the canonical record of the 2026-07-26 workspace backfill but was **not applied by the Supabase CLI** — migration history is desynced (007–009 are live in production but recorded remotely under timestamped names), so `db push` would try to re-run them. **A future `supabase db push` will still try to apply 007–010 together** — reconcile before running it.
